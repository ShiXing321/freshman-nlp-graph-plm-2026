# 工具上手

在PowerShell里进入工作目录：

```powershell
Set-Location -LiteralPath '你的本地项目目录'
$env:PYTHONUTF8='1'
Get-ChildItem
.\.venv\Scripts\python.exe --version
.\.venv\Scripts\python.exe -c 'import torch; print(torch.__version__); print(torch.cuda.is_available())'
```

`Set-Location`切换目录；`Get-ChildItem`列文件；显式使用`.venv`里的Python可避免误用系统Python。当前虚拟环境复用了系统基础包，CUDA PyTorch等关键依赖装在项目环境中。依赖版本见总目录requirements-lock.txt，完整环境包快照见本目录JSON。

重新建立独立环境时，可以运行`./setup.ps1`。它默认创建新的`.venv-reproduce`，单独安装依赖；安装后把报告命令中的`.venv`改为`.venv-reproduce`。如果PowerShell阻止执行脚本，可逐条执行文件里的命令。

Git的作用是记录源代码版本。读取当前版本和修改：

```powershell
git log -1 --oneline
git status --short
git diff --stat
```

`clone`把仓库复制到本地；`pull`取远程更新并合并；`status`查看未提交修改；`diff`查看差异；`commit`记录本地版本；`push`才会发送到远程。提交仓库保存实验代码、报告、截图和结果；上游版本另记在来源版本.json。PLM最初浅克隆并稀疏拉取，之后补齐完整ZIP，并逐项核对300个上游文件的Git blob哈希。

写完代码后先检查语法，再做短运行：

```powershell
.\.venv\Scripts\python.exe -m compileall -q transformers_tasks/local_runs
.\.venv\Scripts\python.exe nlp-beginner/legacy/train_torch.py classification --data-name sentiment_kaggle --model cnn --epochs 1 --limit 1000
```

`--epochs`控制遍历训练集的次数；`--batch`控制每次更新用多少样本；`--lr`是学习率；`--seed`固定随机过程。`--limit 1000`运行一组短实验，会生成独立命名的结果；每份JSON保存实际的数据量和配置。

遇到报错时，从traceback最后一行确定异常类型，再向上找到自己写的文件及行号。此次碰到的实际例子：Windows下NumPy整数默认可能为32位，直接转成torch tensor后CrossEntropy和one_hot报错；把分类标签显式设为`dtype=torch.long`后，损失和梯度计算恢复正常。

日志和结果的分工：终端日志保存过程与报错，JSON保存结构化配置及指标，checkpoint保存可恢复的参数。训练完成后先确认JSON的status为completed，再检查验证选优和最后的测试结果。核查脚本会重新加载检查点并前向运行，验证保存参数能恢复预测。

CUDA显存不足时，先减batch或序列长度，保持串行训练；再考虑梯度累积、混合精度、gradient checkpointing或LoRA。它们解决不同问题：梯度累积让多次小批次合成一次更新；混合精度降低部分张量大小；checkpointing用重算减少激活内存；LoRA减少需要更新的参数。本机的大模型实验采用0.5B与小GPT2，具体参数和数据规模见PLM报告。

下载完成后核对文件大小和发布的SHA256。分块续传需确认Content-Range，ZIP还可验证CRC。哈希不一致时检查下载是否完整及来源是否相同，修复后再训练。
